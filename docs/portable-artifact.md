# Portable personal payload decision

v0.1 uses a directory payload, assembled on each target from the committed npm lock with `npm ci --omit=dev`. The payload contains the PiShip package builds, Pi's published npm package and its production dependency closure, package metadata and assets, declared resources, manifest, lock, and an integrity inventory. It is copied as one unit at install. The payload includes a `piship.mjs` management entry, and a platform-specific command shim points at its `bin/<command>` entry. The same payload directory is the input for later signing, update, and rollback work; the installer does not reconstruct a second runtime.

Node.js 22.19.0 or newer is a documented, separately installed prerequisite. Bundling Node would enlarge the already substantial Pi dependency closure and add patch, signing, native binary, and per-target installer responsibility now. A separate Node prerequisite preserves normal npm handling of Pi's dynamic TypeScript extension loader and native/WASM dependencies. The installed shim checks that Node exists; the launcher checks its minimum version. Neither silently downloads Node or Pi. Installation itself needs no separate runtime install step once Node is present.

The runtime is copied per distribution, with no shared mutable cache. This costs disk space but makes uninstall ownership and isolation explicit. On local macOS arm64 with Node 24.21.0, the assembled personal example occupied about 429 MB. Two successive same-target builds produced the same SHA-256 inventory (`1925a3a926ae6e075d50f6f381f22ff80aa2e5eeeebbae1d710c9354d256b856` at the tested source). File content identity is the current reproducibility claim; filesystem archive metadata and cross-target hashes are not claimed equal.

The relocation check copied the payload outside the checkout, made the original checkout path unavailable, then ran the real branded Pi SDK smoke: Pi 0.87.1 initialized, the declared TypeScript extension and skill loaded from the relocated resources, Pi's read tool read the packaged manifest, and a Pi session persisted. No source checkout path appeared in packaged files or runtime resource paths. The package inventory includes runtime JavaScript, package metadata, assets, themes, images, WASM/native files when provided by the target npm resolution, jiti, and transitive dependencies. `package-lock.json` and its exact resolved package versions/integrities are in the payload and distribution lock. Build-time npm access may be needed; launch uses only the payload.

Default install locations are user-writable and do not edit profiles. Install fails on existing app ID, command, payload, or state by default; `--use-existing-state` is the explicit adoption path for a retained state directory. Uninstall deletes the recorded shim and payload and keeps user state. A separate `purge <id> --yes` removes PiShip-owned state after uninstall. Opaque external provider credentials are outside that ownership boundary and may require manual revocation.

The candidate target is macOS arm64, evidenced locally. Ubuntu x64, macOS hosted-runner architecture, and Windows x64 require PR job results before they are advertised as supported. No standalone binary, npm publication, signature, SBOM, or live authenticated request is claimed in v0.1.
